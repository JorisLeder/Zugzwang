# Bot calibration

Generated by `npm run bots:calibrate` (WP-04) on 2026-10-17. Do not edit by hand – re-run the script after changing
`src/bots/params.ts`, `src/bots/models/*` or the roster.

**Result: all acceptance checks pass.**

## Method

- Positions: 362 positions (every position before a move with more than one legal move) from the
  fixture games: fixture-game (FIXTURE_GAME), Morphy – Herzog von Braunschweig/Graf Isouard, Paris 1858, Anderssen – Kieseritzky, London 1851, Anderssen – Dufresne, Berlin 1852, D. Byrne – Fischer, New York 1956, Kasparov – Topalov, Wijk aan Zee 1999 (`scripts/bots/fixtureGames.ts`).
- Each bot chooses one move per position with its production model (`createBotEngineWithOptions`, Node Stockfish
  `stockfish-19-lite-single`), without the opening repertoire; every bot uses the same random seed 20261016 (common random numbers – the
  differences between bots are less noisy).
- Reference: Stockfish depth 14 on the position before and after the move. Expected-points loss
  L = max(0, EP(best) − EP(played)), EP = win% / 100 from the mover's point of view (Lichess formula, D-07/D-08);
  the reference engine's own best move counts as L = 0.
- Classes (D-07): best L < 0.005 (or the reference best move) · excellent ≤ 0.02 · good ≤ 0.05 · inaccuracy ≤ 0.10 ·
  mistake < 0.20 · blunder ≥ 0.20.
- Compute time = wall time of `chooseMove` in Node (single-threaded WASM, no artificial think time). Think time is the
  suggested artificial delay (`thinkTimeMs`, 1–8 s by complexity; 0 in e2e runs).
- Run time: 976 s.

## Notes

- Targets are the BACKLOG values (criterion 2: best-move share 25–75 % and (inaccuracies + mistakes) ≥ 2 × blunders for the 800–2000 bots; criterion 3: compute ≤ 1 s, think time 1–8 s); none was changed.
- The calibration positions come from master games and a fixture game, so many positions are sharp: absolute loss values are higher than in typical beginner games; check 2a compares the bots with each other, no check uses an absolute loss value.
- Measured on a shared 4-core machine while other packages ran; the movetime caps keep compute ≤ 1 s, but under load the searches are shallower, which slightly raises the losses of the stronger bots.
- Measured in 2 parallel shards (`--json` + `--merge`, same positions and seed); the run time is that of the longest shard.
